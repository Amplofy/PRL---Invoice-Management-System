# PRL-EOMS UI/UX Restructure — Design

Date: 2026-08-27
Status: Approved in chat (scope Q&A + design walkthrough; notifications added per follow-up)

## 1. Overview

Restructure the PRL-EOMS React frontend to match the best UX patterns of the
`EOMS-FE.html` reference while preserving every existing feature and our
Supabase/Express/Render backend. Reference-only Cloudflare views (Information
Gateway, Cloud Backend) are intentionally excluded because they describe a
different hosting stack.

## 2. Scope

Included:

- Navigation restructure (grouped sidebar, new first-class views)
- Invoice Workspace page (`/invoices/:id`)
- Enhanced invoice modal (create/edit): cascade selects, live contract summary
- Workflow Board (kanban) replacing the T1/T2/T3 drill table
- Dedicated Audit Log page
- Dedicated PO History page
- Notifications: header bell + slide-in side panel

Excluded:

- Cloudflare Gateway / Cloud Backend pages (our stack is Supabase/Render/Express)
- Changes to backend data model (all data endpoints already exist)

`frontend/src/components/Sidebar.tsx` — reorganize `NAV_GROUPS`:

| Group | Entries |
|-------|---------|
| Main | Control Tower |

New routes: `/invoices/:id` (workspace), `/audit-log`, `/po-history`.
Update `Header.tsx` `TITLES` + `COMMAND_ITEMS` for the new routes.

## 4. Invoice Workspace (`/invoices/:id`)

New page. Clicking an invoice row (invoices table, kanban card, approvals card,
or follow-up) navigates here.

- **Header bar**: Back button, serial · invoice no, status badge, action bar.
- **Actions** (permission/state gated, reuse existing helpers):
  - Clear (reset form), Delete (blocked if PO versions exist), Approve
    (pending), Reject (pending, requires reason), Generate PO (approved),
    Save.
- **Tabs** (shared `Tabs` component):
  - **Details**: editable form in sections — Invoice Information, Service
    Details (cascade selects), Financial Information, ERP Status (live
    validation summary), right column Contract Summary (live, stamped) +
    Amount in Words.
  - **History**: audit timeline for this invoice (from `/api/audit-log`,
    filtered by entity id, newest first).
  - **PO Versions**: table from `/api/invoices/:id/po` (PO id, generated by,
    generated at, status; view modal).
- Data loading: `GET /api/invoices/:id` (invoice + contract), plus
  service-matrix, cost-elements, po-versions, and audit events.
- Editable in place; Save persists via PUT.

## 5. Enhanced invoice modal (create/edit)

Upgrade `InvoiceFormModal` in `InvoicesPage.tsx`:

- **T1 → T2 → T3 cascade selects** driven by `/api/service-matrix` (replaces
  free-text inputs). Changing a level resets the lower levels and re-resolves
  cost element.
- **Conditional Tanker / Trips** fields from the matched service-matrix row
  (`tanker_required`, `trips`).
- **Auto cost-element resolution** from the matched service-matrix row.
- **Live Contract Summary** panel (side column; stacks below on small screens):
  once a contract is selected — vendor, contract id, value, Used (Approved),
  Remaining, utilization bar, invoice count, and a "this invoice" preview line.
  Used includes the current draft amount; when editing, the invoice's own
  stored amount is excluded from Used and re-added as the preview. This is the
  "stamped with that invoice" behavior.
- **Amount in Words** rendered live under the amount field.
- **Validation summary** chip (count of issues) + inline field errors.
- Shared building blocks (`components/ui/`):
  - `ServiceSelects.tsx` — cascade selects + conditional fields + cost element
  - `ContractSummaryPanel.tsx` — contract + utilization + preview stamp
  - `AmountWords.tsx` — amount-in-words renderer
  - `ValidationSummary.tsx` — issues list
  - `InvoiceActions.tsx` — approve/reject/po/delete/save action bar
- These are shared between the modal and the workspace.

## 6. Workflow Board (kanban)

Replace the drill-down table in `WorkflowPage.tsx` with a 3-column board:

- Columns: Pending / Approved / Rejected. Header shows count + total value.
- Cards: serial no, invoice no, vendor, contract chip, amount, relative time;
  click opens the invoice workspace.
- Top toolbar: search + T1/T2/T3 cascade filters (preserves the existing
  drill-down capability).
- Empty states per column; scrollable columns.

## 7. Audit Log page (`/audit-log`)

New page. Data: `GET /api/audit-log`.

- Filters: action type (Create/Update/Approve/Reject/Delete/PO/Sync), entity
  type, text search.
- Timeline-style list: action badge (toned), entity id, summary, user, relative
  + absolute time.
- Pulled out of the Admin panel tab (Admin keeps its other settings tabs).
- Demo mode: mockApi already serves `/api/audit-log`.

## 8. PO History page (`/po-history`)

New page. Data: `GET /api/payment-orders` (already returns PO + nested invoice
info).

- Distinction from the existing Payment Orders page: **Payment Orders**
  stays the operational, current list (with its print/refresh tools). **PO
  History** is the versioned record — every PO version ever generated across
  all invoices, ordered newest first, framed as a timeline/history (generated
  by, generated at, status at each version).
- Table: PO id, serial, invoice no, vendor, amount, status, generated by,
  generated at.
- Sortable/searchable via `DataToolbar`; view PO detail in a modal (amount in
  words, linked invoice).
- Demo mode: mockApi already serves `/api/payment-orders`.

## 9. Notifications

`frontend/src/components/Notifications.tsx` (new) + wiring in `Header.tsx`.

- **Bell** in header with unread count badge (pulse dot when > 0).
- **Slide-in side panel** from the right (glass, backdrop, close button,
  Escape to close) listing notifications newest first.
- **Notification shape**: type (ok / warn / err / info), title, message,
  relative time, optional `to` route.
- **Sources** (no new table; derived from existing data):
  - Audit-log events pushed by the app's own actions during the session
    (invoice created/updated/approved/rejected, PO generated).
  - On load: computed signals — expiring contracts (≤60 days), high-utilization
    contracts (>95%), and pending approvals.
- Unread state persisted per session (`sessionStorage`); "Mark all read" clears
  the badge; clicking a notification marks it read and navigates if it has a
  route.
- Demo parity: mockApi returns the same audit-log used to seed notifications.

## 10. Data flow & error handling

- Workspace loads invoice, matrix, cost elements, po-versions, audit events
  via existing endpoints; failures → toast + safe back.
- Utilization computed client-side: approved invoices per contract (excluding
  current invoice when editing), matching `contractUtilization()` in the
  reference.
- All destructive actions confirm; delete blocked when PO versions exist
  (server enforces this too).
- Empty states for every list/tab.

## 11. Verification

- `npm run build` (tsc + vite) and `npm run lint` pass.
- Manual checks on preview: workspace open/edit/save from invoices + kanban +
  approvals; modal cascade + contract-summary stamp; kanban filters; audit log
  filters; PO history; notification bell + panel + mark-read + navigation.
- Demo mode parity: every new page works in demo without backend.

## 12. Non-goals

- No backend schema changes.
- No Cloudflare architecture/gateway pages.
- No email template overhaul beyond what exists.
